Security boundary

Official verification, bounded resources, and data-only uploads.

Proofs use the frozen Plonky3 0.6.1 profile and official verifier adapter. Uploaded AIR and traces are declarative data; native code, plugins, WASM, recursion, lookups, and permutation arguments are rejected.

Isolation

Tenant ownership is checked before signing uploads or downloads. Workers receive short-lived object URLs and no database, Stripe, or permanent R2 credentials.

Integrity

AIR, trace, public inputs, release, checkpoint, proof, and bundle identities are digest-bound. The API independently verifies every completed bundle before settlement.

Failure safety

Platform failure, cancellation, verifier rejection, or estimate overflow releases the full reservation. New work can be contained independently of status and recovery operations.

Customer responsibility

Do not submit regulated, highly sensitive, or irreplaceable data. Encrypt data before transport when the supported proof statement permits it, retain your own source data and proof copies, rotate API keys, and revoke unused keys promptly.

Report a vulnerability

Use GitHub private vulnerability reporting. Do not place exploit details, credentials, or customer artifacts in a public issue.
