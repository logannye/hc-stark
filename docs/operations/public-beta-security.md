# TinyZKP Paid Public-Beta Security and Operations Gate

The paid public beta is intentionally limited to declarative Goldilocks AIR packages under the frozen Plonky3 0.6.1 profile. It is not independently audited and has no SLA. Arbitrary native code, WASM, plugins, lookups, permutations, recursion, regulated data, and zero-knowledge claims are out of scope.

## Trust boundaries

- Caddy terminates public TLS. Only the beta API is public; PostgreSQL, PgBouncer, and the worker-control listener are private.
- GitHub supplies identity through authorization-code OAuth with state and PKCE. GitHub login and email are attributes; the numeric GitHub ID is the identity key.
- The API owns tenants, idempotency, admission, credits, leases, verification, and settlement. A worker cannot charge an account.
- Workers receive short-lived object URLs and a WireGuard control credential. They never receive PostgreSQL, Stripe, or permanent R2 credentials.
- R2 is untrusted artifact storage. Lengths, metadata, digests, canonical encodings, statement identity, proof identity, and official verification are checked independently.
- Stripe is authoritative for payment state. PostgreSQL is authoritative for idempotent credit events derived from signed Stripe events.

## Required review

The reviewer records an owner, date, release SHA, evidence links, and disposition for every item below. A critical or high finding blocks `public_beta` authorization.

### Authentication and tenancy

- OAuth state is one-use, expires within ten minutes, and PKCE verifiers are encrypted at rest.
- Callback redirect paths cannot leave the TinyZKP origin.
- Session cookies are `Secure`, `HttpOnly`, `SameSite=Lax`, and use the `__Host-` prefix.
- API keys are high entropy, shown once, stored only as keyed hashes, revocable, and never logged.
- The numeric GitHub identity remains tombstoned after account deletion, preventing a second Sandbox grant.
- Every tenant-owned query includes tenant authorization; cross-tenant identifiers return `404`.

### Artifacts and proving

- Object keys are generated by the API and cannot contain caller-controlled path components.
- Presigned PUTs bind key, length, and digest metadata and expire within fifteen minutes.
- Job admission HEAD-checks every object. The worker then verifies compressed length, BLAKE3, exact expanded length, ordering, whole-trace digest, and canonical field encoding.
- Decompression and JSON limits are enforced before allocation; malformed inputs cannot start proving.
- Predicted RSS, scratch, wall time, plan concurrency, global worker slots, and rate limits fail closed.
- Scratch is `0700` on a `noexec,nodev,nosuid` mount and is cleaned on every terminal path.

### Leases, cancellation, and settlement

- Worker routes are reachable only through WireGuard and require a separate rotatable credential.
- Attempt number, lease epoch, worker identity, release SHA, and expiry are checked on every renewal and completion.
- Stale completion and replay cannot mutate job or credit state.
- Cancellation is polled every heartbeat and durable boundary; queued cancellation releases credits immediately.
- The API downloads and officially verifies the final bundle before settlement.
- Platform failure, verifier rejection, cancellation, or estimate overflow releases the full reservation.
- Concurrent submissions, cancellation, lease expiry, completion, and retries preserve credit-ledger invariants under PostgreSQL row locks.

### Billing

- Only `tinyzkp_public_beta_v1` server-side SKUs can enter Checkout.
- Checkout Sessions are used for subscriptions and top-ups; Customer Portal handles payment methods, invoices, and period-end cancellation.
- Raw Stripe request bytes are authenticated before JSON parsing. Event ID and payload hash conflicts fail loudly.
- Subscription credits are granted only from `invoice.paid`; paid top-ups are granted once from a paid Checkout event.
- `invoice.payment_failed` freezes new paid work without deleting balances, invoices, Portal access, verification, or downloads.
- Nightly reconciliation replays through the normal event processor and never directly edits balances.
- Synthetic live canaries are tagged, refunded/cancelled, and excluded from revenue reporting.

### Infrastructure and recovery

- Production images are digest-pinned, signed with GitHub OIDC, have SPDX SBOMs, and match the authorized release SHA.
- Secrets live outside the checkout in `0400`/`0600` files; no secret or presigned URL appears in logs or evidence.
- PostgreSQL and PgBouncer are not publicly reachable and enforce resource, connection, statement, and lock limits.
- pgBackRest continuously archives WAL to an encrypted private R2 bucket with daily differential and weekly full backups.
- The recovery-key copy is retained separately from the VM and R2 credentials.
- A release-bound restore drill replays WAL, recomputes balances from immutable events, validates API-key authentication, recovers queue state, and verifies a retained proof bundle.

## Incident rollback

`switch-beta-route.sh rollback` blocks signup, Checkout, uploads, and new jobs at Caddy while retaining authenticated job status, bundle downloads, free verification, and Portal access. The worker control plane may finish or cancel already admitted jobs. Rollback does not delete PostgreSQL state, balances, invoices, or R2 bundles.
