## Task 2 — G13 off-box backup + restore runbook

**Files:** `billing/backup.sh`, `deploy/hetzner/setup.sh`, `docs/runbooks/restore.md` (create).

- [ ] **Step 1 — `billing/backup.sh`:** (a) add `api_keys.txt` to the set that gets backed up (copy it alongside the sqlite `.backup`s — a plain `cp` is fine for the flat file). (b) After the local snapshots, push them OFF-BOX to a configurable remote via `rclone`, only if configured:
```bash
# Off-box copy (G13): push the day's snapshot to a remote if configured.
# Operator: `rclone config` a remote and set HC_BACKUP_REMOTE, e.g.
#   export HC_BACKUP_REMOTE="b2:hc-stark-backups"   (Backblaze B2 / S3 / etc.)
if [ -n "${HC_BACKUP_REMOTE:-}" ] && command -v rclone >/dev/null 2>&1; then
  rclone copy "$BACKUP_DIR" "$HC_BACKUP_REMOTE/$(date -u +%Y-%m-%d)" --max-age 25h \
    && echo "$(date -u +%Y-%m-%dT%H:%M:%SZ) Off-box backup pushed to $HC_BACKUP_REMOTE"
else
  echo "$(date -u +%Y-%m-%dT%H:%M:%SZ) WARNING: HC_BACKUP_REMOTE unset or rclone missing — on-disk backup only (G13 NOT satisfied)" >&2
fi
```
(Keep the existing local `.backup` + 30-day prune. The WARNING makes an unconfigured off-box backup loud rather than silent.)
- [ ] **Step 2 — `deploy/hetzner/setup.sh`:** ensure the daily backup cron exists (confirm the existing entry; if it sources an env file, make sure `HC_BACKUP_REMOTE` is available to the cron — e.g. read from `/opt/hc-stark/.env`). Add a one-line note that the operator must `rclone config` + set `HC_BACKUP_REMOTE` for off-box backups to run.
- [ ] **Step 3 — `docs/runbooks/restore.md` (create):** a short, tested-on-paper restore procedure: (a) stop the stack; (b) `rclone copy $HC_BACKUP_REMOTE/<date> /opt/hc-stark/data-restore`; (c) restore `tenant_store.sqlite`, `usage.sqlite`, `api_keys.txt` into `/opt/hc-stark/data`; (d) restart; (e) verify via the health audit.
