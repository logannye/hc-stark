Use the simplest primitive that proves the right thing.

TinyZKP is not a replacement for every log, signature, or audit system. It is valuable when a recipient needs to verify that an encoded state transition followed a rule, without replaying your source system or operating prover infrastructure.

Comparison pages

Authorship

TinyZKP vs signed logs

Signed logs prove who wrote bytes. TinyZKP receipts prove that an encoded state transition is valid.

Best when: signed records include claims a recipient should verify.

Ordering

TinyZKP vs hash chains

Hash chains make tampering visible. Receipts let a verifier check a checkpoint without replaying every event.

Best when: a checkpoint rule matters more than raw ordering alone.

Read comparison

Infrastructure

TinyZKP vs self-hosting

Self-hosting means prover queues, high-memory workers, release compatibility, verifier packaging, and on-call ownership.

Best when: proving is a product feature, not your core infra business.

Expressiveness

TinyZKP vs zkVM provers

zkVMs prove arbitrary program execution. TinyZKP is a narrower hosted receipt API for supported transition statements.

Best when: integration speed matters more than arbitrary code proofs.

Web provenance

TinyZKP vs zkTLS

zkTLS proves facts about web data. TinyZKP proves supported encoded transitions after facts enter your workflow.

Anchoring proves publication. TinyZKP proves validity of the encoded transition.

Choose TinyZKP when

  • A recipient needs to verify a state transition rule.
  • The source system should not be replayed by every verifier.
  • The receipt can travel with an API response, agent output, checkpoint, or audit package.
  • Transparent public parameters are acceptable for the default workflow.

Do not choose TinyZKP just for

  • Authorship without statement validity.
  • Generic private-input claims without a documented template.
  • Arbitrary zkVM, zkML, rollup, or on-chain verifier support as if already live.
  • Sub-second proof generation on every UI interaction.

Still deciding? Start with one receipt.

The fastest way to evaluate TinyZKP is to pick one workflow where a verifier currently trusts logs, prose, screenshots, or replay. Generate a receipt, verify it, then compare the operational cost against your current primitive.
