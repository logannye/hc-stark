Good fit signals

  • The verifier should not replay the producer's system.
  • The statement is a state transition, checkpoint, or accumulator update.
  • The receipt can attach to an API response, agent output, audit record, or customer-facing page.
  • Transparent public parameters are acceptable for the first workflow.

Review first

  • You require private-input zero knowledge.
  • You need a custom predicate or unsupported state machine.
  • You need on-chain verification, restricted runtime verification, or contractual support targets.
  • You are evaluating zkVM, zkML, rollup, or bespoke prover work.

Start with the receipt your buyer will actually inspect.

Do not start by proving everything. Start with one visible receipt that changes a trust boundary, then expand to adjacent workflows once the verifier path and cost model are known.
