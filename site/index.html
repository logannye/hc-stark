Why TinyZKP

Memory is a product constraint, not a benchmark footnote.

The engine is being designed around an explicit ResourcePolicy. The current resource layer preflights RAM and scratch, selects memory or scratch mode, and provides checksummed stores and checkpoint contracts. End-to-end deterministic continuation is not yet implemented.

Bounded resident RAM

Configure the ceiling

The current DFT prototype exercises memory and scratch paths. Tiled double-buffered transforms and an end-to-end ceiling across trace, quotient, and FRI remain release gates.

Verifier compatibility

Keep the trusted boundary upstream

The prototype emits official Plonky3 proof types that are accepted by the unmodified upstream verifier. TinyZKP does not introduce a new transcript, verifier, or proof security profile.

Operational recovery

Make long jobs resumable

Owner-only scratch, atomic manifests, chunk checksums, explicit retention, phase checkpoints, and official challenger-state restoration define the planned recovery contract.
