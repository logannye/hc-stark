Verifiable agent output

Agent prose should carry proof when the action matters.

Natural-language agent output is easy to copy, truncate, hallucinate, or forward without context. TinyZKP turns important state-changing outputs into a structured result plus a proof receipt that humans, services, and other agents can verify.

What changes when output becomes verifiable

Before

Trust the transcript

The recipient reads what the agent said, maybe inspects logs, and still has to trust the producer's runtime.

Receipt

Verify the transition

The output includes a proof object or receipt URL. The verifier checks the encoded transition without replaying the workflow.

After

Store portable evidence

The receipt can travel into support tickets, audit records, API responses, customer pages, and second-agent workflows.

Receipt these outputs

  • Tool-call batches that change records, permissions, quotas, balances, or workflow status.
  • Reconciliation checkpoints and audit summaries.
  • Customer-visible state changes returned from an agent or API.
  • Long-running autonomous workflows where a supervisor needs evidence.

Do not receipt these by default

  • Pure text summaries with no state mutation.
  • Private details that would be exposed in transparent receipt parameters.
  • Claims whose real-world truth was not encoded into the statement.
  • Sub-second UI actions where a signature or log line is enough.

Implementation pattern

1. Agent completes a high-value state-changing tool call.
2. Agent or backend maps public state to a supported TinyZKP statement.
3. TinyZKP mints a receipt through MCP or REST.
4. Final answer includes the business result and receipt_url.
5. Recipient verifies through the public verifier, API, or compatible WASM path.

The winning agent output is not just fluent. It is inspectable.

Start with one output that currently requires screenshots, manual replay, or trust in a transcript. Add a receipt and make the verifier result part of the product surface.
