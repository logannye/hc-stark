Data handling summary

Use TinyZKP for proof receipts, not as a place to store secrets. Buyers should keep private customer data, API keys, and unsupported private inputs out of transparent proof parameters.

What to ask before production

Good production fit

  • You need third-party verification of a state transition.
  • The verifier should not replay your source system.
  • The receipt can be attached to an API response, audit record, agent output, or checkpoint.
  • Transparent public parameters are acceptable for the workflow.

Start a review first

  • You require private-input zero knowledge.
  • You need a custom predicate or unsupported state machine.
  • You need contractual support targets, reserved capacity, or data-retention terms.
  • Your verifier must run on-chain or inside a restricted environment.
