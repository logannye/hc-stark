Developer documentation

Build against the resource contract.

TinyZKP targets official Plonky3 0.6.1 proof types and its unmodified verifier. The public Rust and CLI surfaces describe workload, RAM, scratch, checkpoint, provenance, and benchmark behavior rather than a new proof protocol.

Planned CLI

hc-cli plonky3 doctor --policy resource-policy.json
hc-cli plonky3 prove --manifest workload.json --output proof-bundle.json
hc-cli plonky3 resume --checkpoint checkpoint.json --output proof-bundle.json
hc-cli plonky3 verify --bundle proof-bundle.json
hc-cli benchmark plonky3 --manifest workload.json --baseline conventional --candidate bounded --report report.json

Commands remain implementation-preview until the release gates pass. Generic legacy proving is available only in offline legacy-research builds.

Versioned artifacts

TypePurpose

ResourcePolicyV1

  "mode": "auto",
  "max_resident_bytes": 536870912,
  "max_scratch_bytes": 8589934592,
  "scratch_dir": "/secure/nvme/tinyzkp",
  "max_threads": 8,
  "checkpoint_policy": "retain_on_failure"
}

auto uses memory only below 70% of the declared cap. Preflight rejects insufficient RAM, scratch, invalid permissions, and unsupported profiles before reading the complete input.

Maintenance API

GET /version

Release identity for deployment-skew checks.

GET /healthz

Process liveness only; it does not imply proving availability.

GET /v1/capabilities

Explicit backend, maintenance, proving, verification, checkout, and compatibility state.

Fail closed: prove and account routes return 503 protocol_upgrade; hosted pre-v9 verification returns 422 legacy_statement_unbound.
