Live Self-serve State transition Transparent

accumulator_step

Proves that a declared additive transition chain is internally consistent: the initial value plus every declared delta reaches the final value.

  • Claim: initial + sum(deltas) = final under the supported production proof format.
  • Best for: agent checkpoints, ledger/reconciliation totals, audit accumulators, reserve/liability aggregate updates, and long state-transition traces.
  • Not for: generic private-input privacy, arbitrary programs, business facts that were never encoded, or sub-second UI interactions.
  • Billing: self-serve plans for recurring receipts; Compute for long traces.
curl -X POST https://api.tinyzkp.com/prove/template/accumulator_step \
  -H "Authorization: Bearer tzk_..." \
  -H "Content-Type: application/json" \
  -d '{
    "params": {
      "initial": 1000,
      "final": 1045,
      "deltas": [10, 20, 15]
    }
  }'

Template contract

The template contract is the part of TinyZKP a verifier can reason about. Keep these fields stable in your product, audit packet, or agent output.

FieldTypeRequiredMeaning
template_idaccumulator_stepYesIdentifies the proof template used to mint the receipt.
initialintegerYesThe declared starting accumulator value.
finalintegerYesThe declared ending accumulator value.
deltasinteger arrayYesOrdered transition increments applied between initial and final.
proofreceipt proof objectAfter job successThe proof object returned by GET /prove/{job_id} and accepted by the verifier.

Use the right route for work outside the catalog

Most ZK demand starts as a custom predicate, privacy requirement, or long trace. TinyZKP should not sell those as live templates until the statement, verifier path, data boundary, and audit posture are clear.

Custom state machines

Use pilot review when the transition rule is not expressible as the live accumulator template.
