Agent audit trails

Checkpoint autonomous work with receipts auditors can verify.

Agent audit trails should not be piles of transcripts nobody can replay. TinyZKP lets teams attach compact proof receipts to important checkpoints so reviewers can verify the encoded state transition without needing access to the agent runtime, source database, or full workflow replay.

Why receipts help audit

  • They make checkpoints portable outside the producer system.
  • They give reviewers a machine-checkable artifact instead of only prose.
  • They reduce replay burden when event streams are long.
  • They make agent evidence suitable for customer, operations, and support workflows.

Keep the boundary honest

  • The receipt proves the encoded transition, not every off-chain fact.
  • Transparent parameters must not contain secrets or raw customer data.
  • Private-input and custom predicates should use design review.
  • Use signatures or logs for authorship and source-event custody.

Pilot shape

Pick one audit checkpoint with an owner, verifier, public statement, receipt surface, and cost model. The goal is not a slide deck; it is a real receipt the intended reviewer can verify.

Days 0-3

Name the state transition, verifier, data boundary, and statement shape.

Days 4-8

Generate receipts against sample and live-like checkpoints, then verify no secrets enter transparent parameters.

Days 9-14

Attach the receipt where reviewers will actually see it and decide the commercial rollout path.

The audit artifact should survive outside the agent runtime.

Start with one checkpoint that people already review manually. Make it a receipt-backed workflow, then expand to adjacent checkpoints once the verifier path works.
