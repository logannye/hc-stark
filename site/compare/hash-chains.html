TinyZKP receipts vs hash chains.

Hash chains are excellent for tamper-evident ordering: each record commits to the previous record. TinyZKP receipts solve a different problem: proving that an encoded state transition is valid without asking the verifier to replay the chain.

How they work together

Hash chainCreates a tamper-evident order of events or checkpoints.
TinyZKPProves the checkpoint transition follows the declared arithmetic rule.
VerifierChecks a compact receipt instead of replaying every historical event.

Hash chains are enough when

  • The verifier only needs tamper evidence.
  • The verifier can cheaply replay every event.
  • The application logic is already trusted.

Add TinyZKP when

  • Replay is expensive, unavailable, or undesirable.
  • The verifier needs proof of the transition rule.
  • You want portable receipts for counterparties, agents, or auditors.
