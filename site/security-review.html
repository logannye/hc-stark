Procurement packet

Security review material for evaluating TinyZKP.

This page collects the security and procurement answers buyers usually need before adding TinyZKP to an audit, reconciliation, agent, or long-trace proving workflow. It is intentionally explicit about what is live, what is review-gated, and what data can leave your environment.

Production trust boundary

Live

Hosted proving

TinyZKP receives the parameters needed to mint a receipt for the selected live template, schedules the prove job, and returns proof bytes plus encoded statement metadata.

Live

Public verification

The public verifier requires no API key. It tries first-party WASM first and falls back to TinyZKP's hosted verifier if the local package is behind the current production proof format.

Boundary

Transparent default receipt

The self-serve product is a transparent state-transition receipt. Do not treat it as private-input zero knowledge unless a specific privacy template, review status, and verifier path are documented for your engagement.

Boundary

No business-truth oracle

A proof verifies the encoded statement. It does not prove off-chain facts, event semantics, source-data quality, or compliance assertions that were never encoded into the statement.
