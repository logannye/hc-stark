Diagnose the resource envelope before rerunning.

An OOM is evidence that the current execution and machine do not fit. It is not evidence that every bounded strategy will work—or that a larger machine is the only answer.

Capture the failure you actually have

  • Record trace rows, width, constraint degree, dependency/profile identity, peak RSS, wall time, and the durable phase reached.
  • Distinguish process OOM, cgroup termination, kernel OOM kill, disk exhaustion, and manual interruption.
  • Use synthetic or scrubbed reports; never upload witness or trace data.

Preflight three choices

Conventional

Keep the fast path only when estimated peak use stays within 70% of the declared RAM budget.

Bounded

Use customer NVMe scratch only after the candidate estimate and 10% free-space headroom pass.

Reject

Stop before ingestion when the proof profile, AIR feature, path, RAM, or scratch contract is unsupported.

Evidence before claims

TinyZKP’s resource targets are release gates, not universal achieved results. Use the fixed-host evidence matrix and reproduce the same workload before budgeting production capacity.
