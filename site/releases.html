Release identity

A qualified release binds the Guard version, exact engine source SHA, OCI digest, artifact hashes, schema versions, compatibility profile, release date, SBOM, provenance, signatures, benchmark evidence, and review evidence in one signed channel manifest.

Update policy

Qualified releases are planned quarterly. Old immutable releases are retained because checkpoints are exact-release-bound. A compatibility profile expands only after its complete correctness, resource, recovery, review, and external-use gate is repeated.

No silent activation

The website cannot enable checkout by changing a button or adding a URL. The published commerce configuration must indicate a passed canonical launch gate and contain a separately reviewed hosted-checkout variant before page code makes a purchase control clickable.
