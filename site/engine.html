Engine architecture

A Plonky3 prover designed around a resource contract.

TinyZKP keeps Plonky3's official proof types and verifier authoritative. The implemented resource layer makes RAM, SSD scratch, and artifact provenance explicit; full-pipeline checkpoint recovery and telemetry remain release-gated.

Compatibility first

TinyZKP does not add a new transcript or verifier. The production backend must emit official Plonky3 proof types and pass the unmodified verifier for every supported profile.

Frozen compatibility profile

Exact crate versions, dependency hashes, reference configuration, workloads, and serializer limits are recorded in a machine-readable manifest.

Two execution modes

Memory mode prioritizes throughput. Scratch mode enforces a declared RAM ceiling while preserving deterministic proof results for frozen profiles.

Narrow review boundary

Independent review focuses on transform equivalence, commitments, FRI storage, checkpoint state, parser limits, and resource enforcement.

hc-stream resource layer

ResourcePolicyV1

RAM cap, scratch path and cap, execution mode, thread limit, and checkpoint retention. Auto selects memory only when its estimate is below 70% of the declared cap.

BlockMatrix and MatrixStore

Fallible caller-buffered reads plus memory and scratch stores with canonical field encoding, owner-only permissions, checksums, and lifecycle management.

CheckpointManifestV2

The implemented envelope binds phase and artifact digests to backend, workload, profile, release, policy, and dependency-lock identities. Challenger restoration remains future work.

ResourceEstimate

Mode-specific peak RAM, scratch high-water mark, I/O volume, and phase-cost fields support preflight and later report reconciliation.
