Security posture

Keep protocol trust upstream; review the new prover boundary.

TinyZKP does not define a new transcript, proof format, or verifier. Official Plonky3 proof types and the unmodified verifier remain authoritative. TinyZKP's review boundary is prover-side storage, algebraic equivalence, checkpoint state, parsing, and resource enforcement.

Implementation boundary

Algebraic equivalence

Tiled transforms, streaming commitments, quotient evaluation, and blockwise FRI must match the pinned Plonky3 reference path.

Recovery integrity

Checkpoint manifests bind dependency, workload, input, policy, release, challenger state, and artifact digests before resume.

Resource enforcement

Preflight, cgroup measurements, scratch caps, owner-only files, corruption checks, and cancellation behavior are part of the reviewed product.

Release requirements

  • Fibonacci and Poseidon2 proofs verify with the unmodified official verifier
  • Memory and scratch modes agree for frozen deterministic profiles
  • Crash, resume, corruption, malformed-bundle, and parser-fuzz suites pass
  • No unresolved critical or high review finding
  • 1M rows achieve at least 4× RAM reduction within 3× wall time
  • 10M rows remain within 2 GiB RSS and preflight scratch tolerance
  • One external design-partner integration succeeds
  • Signed checksums, SBOM, compatibility manifest, and matching release identities

Report a security issue

Submit only a high-level summary through the HTTPS security request form. TinyZKP will follow up through the no-email channel you choose and establish a private channel for sensitive details. Do not place secrets, witnesses, credentials, customer data, or exploit payloads in the public form.
