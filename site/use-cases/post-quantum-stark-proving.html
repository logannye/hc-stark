Use case

Transparent, hash-based STARK receipts without a trusted setup.

TinyZKP uses STARK-style proofs for state-transition attestation. The public value proposition is simple: no trusted setup ceremony, hash-based verification, and a prover architecture designed around low RAM.

Read the quickstart

Why buyers care

  • Receipts can be verified by third parties.
  • There is no per-customer trusted setup ceremony.
  • The low-memory prover changes the cost structure for long traces.

Where TinyZKP is narrow

The default public product is state-transition receipts, not every possible STARK workload. That narrowness keeps the self-serve product understandable and defensible.

Pricing fit

For small receipts, start free and upgrade as volume grows. For large traces, Compute prices at $0.50/M steps so sporadic workloads avoid monthly high-RAM infrastructure.

Security language

Soundness parameters are audit-pending and described honestly in the security docs. The website should not rely on unaudited bit-strength marketing claims.
