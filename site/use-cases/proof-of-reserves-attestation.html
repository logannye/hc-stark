Use case

Proof-of-reserves checkpoints with transferable verification.

For reserve or liability reporting, the first paid use case is often not a full privacy protocol. It is a verifiable checkpoint: a running total moved from the previous committed value to the new value by declared deltas.

Start free

Current primitive

accumulator_step proves additive checkpoint transitions. It is a fit for reserve-total, liability-total, or reconciliation workflows where you already publish the relevant aggregate.

Why pricing matters

Reserve proofs can be sporadic and large. Compute keeps those proofs usage-based at $0.50/M trace steps instead of forcing you to keep a high-RAM prover box running all month.

Checkpoint request

curl -X POST https://api.tinyzkp.com/prove/template/accumulator_step \
  -H "Authorization: Bearer tzk_..." \
  -H "Content-Type: application/json" \
  -d '{"params":{"initial":9800000,"final":9812400,"deltas":[5000,7400]}}'

What it proves

The arithmetic transition from prior total to new total is internally consistent.

What it does not prove

It does not by itself prove asset custody, bank balances, liability completeness, or private set membership. Those need additional evidence or future templates.
