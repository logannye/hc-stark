Use case

Tamper-evident audit-log checkpoints that verify without replay.

Audit logs are useful only if a counterparty can trust the checkpoint. TinyZKP lets you attach a receipt proving that a running accumulator advanced from a prior checkpoint to a new checkpoint by the declared steps.

Start free

How to model it

Map each event to a deterministic numeric delta in your own application, then prove the checkpoint transition with accumulator_step. The receipt is small enough to store beside the checkpoint row.

Why this beats a raw log

  • The verifier does not need your log database.
  • The receipt is transferable to auditors or counterparties.
  • Long checkpoints use Compute pricing instead of high-RAM prover hardware.

API shape

curl -X POST https://api.tinyzkp.com/prove/template/accumulator_step \
  -H "Authorization: Bearer tzk_..." \
  -H "Content-Type: application/json" \
  -d '{"params":{"initial":24000,"final":24342,"deltas":[101,77,164]}}'

Best paid fit

Teams pay when checkpoints get large enough that replay, storage, or high-RAM proving is annoying. Compute keeps sporadic large checkpoints usage-based at $0.50/M trace steps.

Limit

TinyZKP proves the transition arithmetic, not the semantic truth of every event. Your application must define the event-to-delta mapping.
