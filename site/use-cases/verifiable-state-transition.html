Use case

Verifiable state transitions without re-running the system.

TinyZKP mints a transparent ZK-STARK receipt that says: start at X, apply these deltas, and reach Y. A counterparty can verify the receipt without access to your database, worker logs, or replay infrastructure.

Get an API keyTry in browser

What the receipt proves today

The live self-serve template is accumulator_step. It proves that a declared additive transition chain is internally consistent: initial + sum(deltas) = final. External cryptography audit remains tracked separately in the Trust Center.

Where it fits

  • Ledger or balance reconciliation
  • State-machine checkpoints
  • Long audit trails priced by trace steps on Compute
  • Transferable receipts attached to API responses or records

Copy-paste proof request

curl -X POST https://api.tinyzkp.com/prove/template/accumulator_step \
  -H "Authorization: Bearer tzk_..." \
  -H "Content-Type: application/json" \
  -d '{"params":{"initial":1000,"final":1045,"deltas":[10,20,15]}}'

Then poll /prove/<job_id> and send the proof object to tinyzkp.com/verify. For embedded verification, use the @tinyzkp/verify WASM package where it supports the receipt format.

Pricing fit

Small receipt volume uses Free, Developer, Pro, or Scale. Very long traces use Compute at $0.50 per million trace steps, which is designed to undercut the high-RAM prover infrastructure you would otherwise operate.

Honest limits

This is not a general zkVM, not a finished zkML service, and not a privacy range proof. More proof types are in development; the public default is state-transition receipts.
