Cursor MCP integration

Make Cursor agent workflows return verifiable receipts.

Cursor can connect to external tools through MCP. Add TinyZKP when the coding agent runs scripts, migrations, data changes, release checks, or workflow automations where a receipt should travel with the output.

Cursor MCP server config

Use Cursor Settings > Tools & MCP, or the MCP configuration file supported by your Cursor workspace, and add TinyZKP as a remote MCP server. Keep API keys in approved local or team-managed configuration.

{
  "mcpServers": {
    "tinyzkp": {
      "url": "https://mcp.tinyzkp.com",
      "headers": {
        "Authorization": "Bearer tzk_..."
      }
    }
  }
}

Cursor's current documentation describes MCP as the way to connect Cursor to external tools and data sources. If your build exposes a different UI around MCP server setup, use the same TinyZKP endpoint and authorization header.

When to call TinyZKP

Do not receipt every chat turn. Receipt the state-changing step that a reviewer, teammate, auditor, customer, or later agent may need to verify.

if action mutates durable state:
  prove transition with TinyZKP
  attach receipt_url to result
  store proof job ID beside checkpoint

Best first Cursor workflows

Data backfills

Receipt a supported state transition after the agent runs a backfill or reconciliation script.

Quota or counter changes

Attach proof receipts to internal tools that update counters, quotas, balances, or workflow checkpoints.

Review artifacts

Return receipt URLs in PR notes, support reproductions, or audit packages when reviewers need compact evidence.

Use the agent receipt envelope

Return structured output with the agent result, receipt URL, template ID, verifier URL, and proof boundary. This lets downstream systems parse the evidence without reading natural language.
